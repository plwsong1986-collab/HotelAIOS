# Changelog Principles

Record only meaningful project changes.

Appropriate changelog entries include:

- New modules
- Major documentation additions
- Repository restructuring
- Architectural changes
- Governance improvements
- Engineering standard updates
- Lifecycle changes
- Significant workflow improvements

Do not record:

- Typographical corrections
- Formatting adjustments
- Minor wording improvements
- Routine maintenance updates

---

# Entry Format

Each release entry should include:

- Version
- Release Date
- Added
- Changed
- Removed

Optional sections:

- Fixed
- Deprecated
- Security

Entries should remain concise, factual, and chronological.

---

# Maintenance Rules

- Always append the newest release to the top of the version history.
- Never rewrite published historical records except to correct factual errors.
- Every entry should accurately reflect the official state of the project at the time of release.
- Changelog entries should describe **what changed**, not **how it was implemented**.
