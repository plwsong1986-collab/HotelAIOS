# Purpose

This document defines the release governance and publication process for the HotelAIOS website.

It establishes standardized procedures for planning, reviewing, approving, publishing, maintaining, and retiring website content and documentation.

This document is the Single Source of Truth (SSOT) for website release governance.

---

# Overview

The Release Process ensures that website changes are delivered in a controlled, consistent, and traceable manner.

Every release should preserve content quality, architectural consistency, accessibility, SEO integrity, and alignment with the HotelAIOS Knowledge Module.

---

# Scope

This document includes:

- Release lifecycle
- Review process
- Approval process
- Publication process
- Version management
- Change governance
- Documentation updates

This document does not include:

- CI/CD implementation
- Deployment scripts
- Source control workflows
- Infrastructure management
- Backend release procedures

These remain owned by their corresponding engineering teams.

---

# Release Principles

Every release should be:

- Planned
- Reviewed
- Approved
- Documented
- Traceable
- Repeatable
- Reversible
- Consistent

No release should bypass the defined governance process.

---

# Release Lifecycle

The standard release lifecycle consists of:

1. Planning
2. Draft
3. Review
4. Approval
5. Release
6. Verification
7. Maintenance
8. Archive (when applicable)

Each phase should be completed before progressing to the next.

---

# Review Requirements

Before release, verify:

- Information Architecture consistency
- Navigation consistency
- Content quality
- Metadata completeness
- Accessibility compliance
- SEO readiness
- Cross-document references
- SSOT ownership boundaries

All review findings should be resolved before publication.

---

# Version Management

Each published document should include:

- Version
- Status
- Last Updated
- Change summary
- Ownership

Version history should remain clear and traceable.

---

# Change Governance

Significant changes should include:

- Architecture review
- Documentation review
- Cross-module impact assessment
- Stakeholder approval
- Release documentation

Governance should maintain long-term consistency across the Website Module.

---

# Relationship with Knowledge

Website releases should remain synchronized with the authoritative Knowledge Module.

Business knowledge changes should originate from the Knowledge Module before being reflected on the website.
